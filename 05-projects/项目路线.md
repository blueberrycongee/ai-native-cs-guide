# 项目地图

这个目录收敛能连接多个概念的项目形态。项目不是作业清单，而是把方向、系统组件和工程问题放到同一个场景里看。

## 本地资料整理 Agent

这个项目形态让 [[Agent]] 在一个小型 Markdown 仓库里工作：读取文件、整理摘要、指出缺口，并在需要时提出修改建议。

相关组件：

- [[Agent Loop]]：目标、状态、工具调用、观察结果和停止条件。
- [[Tool Use]]：`list_files`、`read_file`、`search_text` 这类工具的 schema 和权限边界。
- [[Context Engineering]]：文件片段、历史步骤和当前目标如何进入上下文。
- [[Evals]]：固定仓库、固定任务和输出可追溯性。
- [[Security]]：目录边界、敏感文件和工具权限。

常见工程问题包括工具越权、循环停止、日志证据、上下文膨胀和模型声称读过但实际没有工具调用。

参考项目：

- [LangGraph](https://docs.langchain.com/oss/python/langgraph)：durable execution、streaming、human-in-the-loop。
- [OpenAI Agents SDK](https://platform.openai.com/docs/guides/agents-sdk/)：agent、handoff、tool、trace。
- [Microsoft AutoGen](https://autogenhub.github.io/autogen/docs/Use-Cases/agent_chat/)：multi-agent conversation 和工具参与。

## 带引用的 RAG 问答系统

这个项目形态围绕一组固定文档做问答，并把答案连接回原始证据。

相关组件：

- [[Embedding]]：查询和文档向量。
- [[RAG]]：切块、检索、重排和引用。
- [[Context Window]]：证据数量和输出预算。
- [[Evals]]：检索命中、引用支持和答案忠实度。
- [[Metadata Filtering]]：权限、时间和版本过滤。

常见工程问题包括引用不支持结论、旧索引残留、多用户资料混淆、数字和代码符号召回差。

参考项目：

- [LlamaIndex](https://docs.llamaindex.ai/)：ingestion、index、query engine、evaluation。
- [Haystack](https://docs.haystack.deepset.ai/docs/intro)：pipeline 和 document store。
- [Qdrant](https://qdrant.tech/documentation/) / [Milvus](https://milvus.io/docs)：向量库和 metadata filter。

## 模型调用网关

这个项目形态封装模型 API，把鉴权、流式输出、日志、超时、重试和成本记录放在同一层。

相关组件：

- [[HTTP]]：请求、响应、状态码、超时和取消。
- [[SSE]] / [[Streaming Response]]：模型输出、工具事件和错误事件。
- [[API Auth]]：用户身份和供应商 key 的边界。
- [[Cost]]：input tokens、output tokens、latency 和 error type。
- [[Model Gateway]]：模型供应商、错误分类、trace id 和配额。

常见工程问题包括 SSE 被代理缓冲、用户取消后上游请求继续运行、错误类型混在一起、token 和成本缺少记录。

参考项目：

- [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)：托管模型接口。
- [vLLM OpenAI-compatible server](https://docs.vllm.ai/en/latest/getting_started/quickstart.html)：自部署模型兼容 OpenAI API 的形态。

## 小模型训练到后训练流水线

这个项目形态把小规模训练、指令微调、偏好优化和评测放在同一条链路里。

相关组件：

- [[Pre-Train]]：tokenizer、数据管线、训练循环和 checkpoint。
- [[Post-Train]]：SFT、DPO、GRPO 的输入格式和行为变化。
- [[Evals]]：loss、生成样例、任务输出和回归样例。
- [[Cost]]：GPU 时间、失败重跑和实验复现。

常见工程问题包括数据太小却期待通用能力、只看 loss 不看生成样例、训练格式和推理格式不一致、数据版本缺失。

参考项目：

- [nanoGPT](https://github.com/karpathy/nanoGPT)：`model.py`、`train.py` 和小规模训练循环。
- [LitGPT](https://github.com/Lightning-AI/litgpt)：pretrain、finetune、evaluate、deploy workflow。
- [TRL](https://huggingface.co/docs/trl)：SFT、DPO、GRPO 等后训练方法。
