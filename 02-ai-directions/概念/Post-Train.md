# Post-Train

Post-Train 是预训练之后让模型更适合任务和产品场景的一组方法。它包括指令微调、偏好优化、拒答策略、工具使用数据、reward model、RLHF/GRPO 和评测。

方向总览见 [[Post-Train 方向]]。

## 方向边界

Post-training 改的是模型行为：更会按指令回答、更稳定输出格式、更符合偏好、更懂拒答和工具调用。它不等于把新知识塞进模型，也不替代权限、安全和产品校验。

很多用户感觉到的“模型性格”来自这里：愿不愿意回答、回答多啰嗦、是否会按 JSON 输出、是否倾向保守拒答。

## 典型工程形态

一个 post-training pipeline 通常包括：

- SFT 数据集：示范模型应该如何完成任务。
- 偏好数据：比较两个答案哪个更好。
- 训练配置：LoRA/QLoRA、batch、lr、模板。
- eval 集：格式、事实、拒答、安全和任务成功率。
- 推理对比：微调前后同一批样例。

真正难的是数据和评测。训练脚本只是 pipeline 的一部分。

## 和其他方向的关系

- 依赖 [[Pre-Train]] 提供基础能力。
- 和 [[RL]] 在 RLHF、GRPO 等方法上交叉。
- 和 [[Evals]] 强绑定，没有 eval 就不知道行为是否变好。
- 和 [[Tool Use]] 相关，工具调用模型需要数据和系统双重约束。
