# Agent 方向

Agent 方向研究模型如何围绕目标、上下文、工具和反馈循环工作。它的位置在应用层和系统层之间：既要懂 [[LLM]] 和 [[Prompting]]，也要处理工具权限、日志、成本、失败恢复和 [[Evals]]。

更完整的总览见 [[Agent]]。这页只说明它和其他 AI 方向的边界。

## 方向边界

一个 Agent 系统至少要有：

- 目标：用户或系统给出的任务。
- 状态：当前上下文、历史步骤、工具结果。
- 工具：搜索、文件、浏览器、数据库、代码执行或业务 API。
- 循环：根据反馈决定继续、修正或停止。
- 边界：权限、成本、风险和完成标准。

如果系统只是一次性生成文本，它更像普通 LLM 应用。如果它能用工具改变外部状态，就进入 Agent 问题域。

## 典型工程形态

常见形态包括：

- coding agent：读代码、改文件、运行测试、根据失败继续。
- research agent：搜索资料、筛选来源、生成带引用的报告。
- workflow agent：围绕业务流程调用多个 API。
- personal agent：在用户授权范围内处理消息、日程、文件和任务。

这些系统的共同难点不是“让模型更聪明”，而是让模型的行动可控、可追踪、可停止。

## 和其他方向的关系

- 依赖 [[Context Engineering]]：决定每一步给模型看什么。
- 依赖 [[Tool Use]]：把模型输出变成外部动作。
- 依赖 [[Security]]：工具权限和数据隔离不能交给 prompt。
- 依赖 [[AI Infra]]：流式输出、日志、重试和成本控制。
- 可能用到 [[RAG]]：让 Agent 读取外部知识。
