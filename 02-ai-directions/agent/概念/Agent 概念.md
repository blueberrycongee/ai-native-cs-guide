# Agent 概念

这页是 Agent 方向的最小概念地图，不追求完整。先把会反复出现的概念放到一起，方便读 [[Agent]]、[[Agent 开源项目]] 和项目代码时跳转。

## 核心循环

Agent 的基本结构是 [[Agent Loop]]：目标、上下文、模型、工具、反馈之间形成循环。

循环不一定复杂。一个简单 Agent 可以只是：

1. 读用户目标
2. 判断需要什么信息
3. 调用一个工具
4. 根据结果生成下一步
5. 判断是否结束

复杂系统会加入 memory、planning、权限确认、日志和 eval，但不要一开始就把这些都塞进去。

## 工具和行动

[[Tool Use]] 是 Agent 区别于普通聊天机器人的关键。模型生成文本不危险，模型驱动工具执行动作才危险。

学习时重点看：

- 工具输入输出是否结构化
- 工具调用前是否有权限检查
- 失败结果如何回到模型上下文
- 高风险动作是否需要用户确认

## 推理模式

[[ReAct]] 是理解 Agent 的经典入口。它把 reasoning 和 acting 交替组织起来，让模型能一边想一边使用工具。

不要把 ReAct 当固定模板。它更像一种提醒：很多任务不是一次生成答案，而是需要观察、行动和修正。

## 状态和记忆

[[Memory]] 解决跨步骤、跨会话的信息保留问题。

当前任务状态、工具结果和关键决策记录清楚之后，长期记忆才有稳定的来源。长期记忆一旦做错，会把错误信息带进后续任务。

## 单 Agent 和多 Agent

[[Single Agent vs Multi-Agent]] 讨论什么时候需要多个 Agent。

默认先做单 Agent。多 Agent 只有在角色、权限、任务并行或评审机制确实有价值时才引入。否则它只会增加调试难度。

## 可复用流程

[[Skills]] 是把某类任务的做法沉淀成可复用工作流。它对长期维护 Agent 很重要，因为真实系统不能每次都靠用户重新解释规则。
