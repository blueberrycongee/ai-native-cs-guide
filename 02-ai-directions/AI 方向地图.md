# AI 方向地图

这个仓库先把 AI 相关方向分成五条主线：[[Agent]]、[[AI Infra]]、[[Pre-Train]]、[[Post-Train]] 和 [[RL]]。

它们不是互斥专业。真实项目里经常交叉。分开的目的只是为了让初学者先知道自己在学什么，不要把应用开发、模型训练、推理部署和强化学习混成一团。

## 先看公共基石

进入任何方向前，先理解这些概念：

- [[Transformer]]
- [[Attention]]
- [[Token]]
- [[Embedding]]
- [[Context Window]]
- [[Inference]]

不要求一次学完。至少要知道它们会怎样影响成本、上下文、延迟和项目边界。

## 五条主线

### Agent

[[Agent]] 关心的是模型如何围绕目标使用上下文、工具和反馈循环工作。

适合先做项目的人。你可以从一个很小的 coding agent、资料整理 agent 或工具调用 agent 开始，很快会碰到 [[Prompting]]、[[Tool Use]]、[[Context Engineering]]、[[RAG]] 和 [[Evals]]。

### AI Infra

[[AI Infra]] 关心训练、推理、数据、评测、部署和成本。

如果你对系统、性能、平台、可观测性和工程稳定性更感兴趣，这条线更合适。它不像应用层那样马上有可见 UI，但更接近 AI 系统能否稳定运行的问题。

### Pre-Train

[[Pre-Train]] 关心模型在大规模数据上学习通用能力的过程。

这条线门槛高，通常需要深度学习、分布式训练、数据工程和大量算力背景。初学者不一定要先走这里，但应该知道预训练决定了模型能力的底座。

### Post-Train

[[Post-Train]] 关心模型预训练之后如何变得更可用，比如指令微调、偏好优化、对齐和评测。

它连接模型能力和真实使用体验。很多看起来像“模型性格”的问题，背后都和 post-training 有关。

### RL

[[RL]] 关心智能体如何通过奖励和反馈学习策略。

在大模型时代，RL 常和 post-training、工具使用、环境交互、代码生成评测放在一起讨论。它不等于背几个强化学习算法，而是要理解奖励、探索和反馈设计。

## 怎么选第一条路

如果你想尽快做出东西，先从 [[Agent]] 或 [[RAG]] 项目开始。

如果你喜欢底层系统，先补 [[Inference]]、服务部署、观测和成本，再进入 [[AI Infra]]。

如果你想做模型训练研究，先确认自己能承受数学、深度学习和算力门槛，再看 [[Pre-Train]] 和 [[Post-Train]]。

如果你对“让模型在环境里试错学习”感兴趣，再把 [[RL]] 作为重点。不要只因为它听起来高级就先学。
