# 项目路线

这个目录用于收敛项目，不做灵感清单。

一个项目只有在能验证能力时才值得写进来。能跑 demo 不够，至少要说明它验证什么能力、会遇到哪些概念、怎样判断是否可用。

## 当前优先项目

### 本地资料整理 Agent

目标：让 [[Agent]] 读取一个小型 Markdown 仓库，按用户目标整理摘要、指出缺口或提出修改建议。

验证能力：

- [[Context Engineering]]
- [[Tool Use]]
- [[Agent Loop]]
- [[Evals]]
- [[Security]]

判断标准：

- 读了哪些文件可追踪
- 工具调用有日志
- 输出能引用来源
- 失败时能说明缺少什么信息
- 不会越权读取无关目录

### RAG 问答系统

目标：对一组固定文档做问答，并提供引用。

验证能力：

- [[Embedding]]
- [[RAG]]
- [[Context Window]]
- [[Evals]]

判断标准：

- 找不到证据时会拒答
- 答案能回到原文
- 能区分检索失败和生成失败
- 文档更新后索引能更新

### 模型调用网关

目标：封装模型 API，提供鉴权、流式输出、日志、超时和重试。

验证能力：

- [[HTTP]]
- [[SSE]]
- [[Streaming Response]]
- [[API Auth]]
- [[Cost]]

判断标准：

- 首 token 延迟可记录
- 用户取消后上游请求能停止
- 429、401、5xx 有不同处理
- API key 不暴露到前端

## 写项目文档的规则

项目文档不写成简历包装。每个项目都要回答：

- 这个项目验证什么能力
- 最小可做版本是什么
- 哪些地方容易做成假 demo
- 如何用 eval 或人工检查判断结果
- 需要链接哪些概念和外部资料
