# AI Native CS Guide

这是一个给中国计算机学生和自学者看的 AI 学习笔记库。

它不是传统 CS 路线图，也不是资料收藏夹。我们想做的是一份能被长期维护的学习地图：先讲清楚 AI 的基础概念，再讲行业方向，最后落到项目、开源代码和真实工程问题。

如果你想参与维护这个仓库，重点不是补更多链接，而是写出能帮助别人少走弯路的文档。

## 这个仓库做什么

这个仓库关心的问题很具体：

> 一个计算机学生想进入 AI 相关方向，应该先理解什么，接着看哪些方向，最后用什么项目建立能力？

我们会按学习顺序整理内容：

1. AI 的公共基础，比如 [[Transformer]]、[[Attention]]、[[Token]]、[[Embedding]]
2. AI 行业方向地图，比如 [[Agent]]、[[AI Infra]]、[[Pre-Train]]、[[Post-Train]]、[[RL]]
3. AI 应用工程基础，比如 [[HTTP]]、[[WebSocket]]、[[SSE]]、[[Streaming Response]]
4. AI 系统常用能力，比如 [[LLM]]、[[Prompting]]、[[Context Engineering]]、[[RAG]]
5. 具体方向的项目路线、开源项目和信息来源
6. 经典论文深挖，把关键论文连接到概念、工程实现和可验证项目

有些知识值得自己写，有些不值得。协议细节、论文推导、API 参数这类内容，如果外部资料已经讲得很好，我们会直接链接过去。这个仓库更应该解释：为什么要看、先看哪部分、看到什么程度。

## 这个仓库不做什么

这里不会重写一套完整的前端、后端、数据库、算法或深度学习教材。

传统 CS 仍然重要。HTTP、WebSocket、SSE、数据库、调试、部署、工程质量，这些都会在 AI 项目里出现。但我们只会围绕 AI 场景讲它们，比如模型流式输出、Agent 状态同步、API 调用、长任务取消和重试。

这个仓库也不打算做：

- 大而全的资料列表
- 培训班式学习路线
- 为简历关键词堆出来的项目清单
- 没有判断标准的资源推荐
- 把别人的文档重新抄一遍的二手教程

## 怎么读

推荐按编号目录读，而不是从某个热门词开始跳。

目标结构大致是：

```text
01-foundations/
02-ai-directions/
03-engineering-basics/
04-ai-systems/
05-agents/
06-ai-infra/
07-pre-train/
08-post-train/
09-rl/
10-projects/
11-papers/
90-resources/
```

前两部分先建立基本判断：AI 的底层概念是什么，行业里有哪些方向。后面再按自己的项目或兴趣进入具体路径。

如果你是第一次来，可以先看：

- [[GOAL]]：这个仓库的目标、写作标准和结构规划
- [[AI 方向地图]]：先判断几条主要方向的边界
- [[项目路线]]：用项目理解自己应该补哪些概念
- [[经典论文深挖]]：用论文理解 AI Native 系统背后的关键机制
- [[Agent]]：目前优先展开的具体方向
- [[Skills]]：一篇相对完整的 Agent 概念文档

每个重点方向不只看路径页。进入一个方向时，优先按这个顺序读：

1. 方向首页，例如 [[AI Infra 方向]]、[[Pre-Train 方向]]、[[Post-Train 方向]]、[[RL 方向]]
2. 路径页，例如 [[AI Infra 路径]]
3. 信息来源、开源项目、框架和工具
4. `概念/` 下的核心教程页

## 用 Lumina Note 阅读

这个仓库是 Markdown 笔记库，内部链接使用双括号：

```md
[[Transformer]]
[[Agent]]
[[Context Engineering]]
```

在 GitHub 上可以直接读 Markdown。但如果想要更好的双向链接和笔记浏览体验，可以把仓库 clone 到本地，用 [Lumina Note](https://github.com/blueberrycongee/Lumina-Note) 打开。

```bash
git clone https://github.com/blueberrycongee/ai-native-cs-guide.git
```

Lumina Note 是一个 Markdown 笔记项目，支持双向链接，适合阅读这种不是线性教材的知识库。

## 怎么贡献

欢迎贡献，但希望保持克制。

适合贡献的内容：

- 清楚的概念解释
- 真实项目路线
- 高质量外部资料的筛选和说明
- 开源项目阅读笔记
- 学习某个方向时踩过的坑
- 对某个方向边界的整理

不适合贡献的内容：

- 没验证过的学习路线
- 只有链接、没有判断的资料堆
- AI 生成后没有认真改过的文字
- 复制官方文档或别人的博客
- 只服务传统面试八股的内容

写文档时请尽量做到：

- 直接说清楚这个内容解决什么问题
- 内部概念使用 `[[...]]` 双向链接
- 外部资料使用普通 Markdown 链接
- 不把概念文档写成 API reference
- 如果一段内容开始变成大量字段和参数，优先链接外部资料
- 不写空泛口号，不写看起来很完整但没法指导学习的段落

更具体的目标和写作规则见 [[GOAL]]。
