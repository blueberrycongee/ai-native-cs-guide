# AI Native CS Guide

给中国学生和自学者看的 AI Native CS 学习笔记。

这个仓库不想再写一份“先学语言，再学框架，最后刷题”的路线图。这里关心的是另一个问题：

> 如果目标是尽快做出可用的 AI 产品、Agent、自动化工具或个人项目，应该先学什么，哪些东西可以晚点再补？

## 这个仓库做什么

很多 CS 学习路线默认从这些内容开始：

1. 学一门编程语言
2. 学数据结构和算法
3. 学前端、后端、数据库、框架
4. 做几个 CRUD 项目
5. 刷题、背八股、找实习

这条路不是没用，只是不该自动成为所有人的主线。尤其是当你想做 AI 相关项目时，很多问题会更早出现：

- 怎么用 AI 帮自己学习、写代码和调研
- 怎么调用 LLM API，并处理上下文、结构化输出、工具调用和成本
- 怎么做 RAG、workflow、agent、multi-agent system
- 怎么让模型读写文件、调用 API、运行命令、处理外部数据
- 怎么评测 AI 系统，而不是停在一个能跑的 demo
- 怎么把 AI 能力做成产品、自动化流程或个人工具

这个仓库会围绕这些问题整理资料、项目路线和概念笔记。

## 这个仓库不做什么

这个仓库不会系统性地教：

- 前端框架八股
- 后端框架八股
- Java / Go / Python 面试题大全
- 传统 CRUD 项目教程
- 算法竞赛式刷题路线
- 为了简历关键词而堆技术栈的学习清单

这些东西有价值，但不放在这份路线的中心。

如果某个项目需要 React、Next.js、FastAPI、PostgreSQL、Docker 或其他工具，这里会尽量链接到已有资料，不在仓库里重写一遍教程。

## 原则

### 1. Builder first

学习目标应该落到产出上：能不能做出东西。

这里的 Builder 指愿意自己找问题、设计方案、用工具、做验证的人。你不用创业，也不用做商业产品，但最好把学习和构建绑在一起。

### 2. Link, do not rewrite

互联网上已经有大量教程、文档、论文、课程和项目。这个仓库不重复造轮子。

这里主要做三件事：

- 判断：哪些该学，哪些只是噪音
- 顺序：先学什么，后学什么，什么可以遇到再查
- 连接：把已有靠谱资源放到一条可执行的路线里

### 3. Learn by projects

AI Native 能力很难靠看文章获得。很多问题只有动手做项目才会遇到：

- prompt 为什么不稳定
- RAG 为什么会检索错
- agent 为什么会乱调用工具
- 上下文为什么会爆
- 成本为什么会失控
- demo 为什么离真实产品还有距离

所以这个仓库会先补项目路线，不只列概念。

### 4. Traditional CS 是工具，不是身份

传统 CS 能力仍然有价值。编程、网络、数据库、系统设计、工程质量、调试能力都不会消失。

但它们应该服务于构建目标，不该变成身份焦虑。不要为了“看起来像科班”把大量时间花在低收益内容上。

## 写给谁

这份笔记写给：

- 中国大学生、研究生、自学者
- 想从传统 CS 路线转向 AI Native 路线的人
- 想做 AI 产品、Agent、自动化工具、个人项目的人
- 不想被培训班、八股、焦虑营销牵着走的人
- 愿意读英文资料、写代码、做项目、持续修改的人

如果你的目标是短期冲击传统大厂后端岗位，这个仓库可能不是最直接的面试路线。

## 组织方式

这个仓库不会按 `01`、`02`、`03` 这种线性章节组织。

AI Native 的学习路径不是固定流水线。这里按方向组织笔记，读者可以根据自己的项目和当前能力选择路线。

初步会按照这些方向整理：

- `agents`：agent loop、planning、tool use、memory、multi-agent
- `ai-literacy`：AI 基础认知、学习方法、信息差和常见误区
- `llm`：LLM 基础、API 调用、token、上下文、结构化输出
- `prompting`：prompt engineering、context engineering、任务拆解
- `rag`：检索增强生成、向量数据库、chunking、rerank、知识库
- `workflow`：自动化流程、human-in-the-loop、任务编排
- `evals`：评测、回归测试、质量控制、成本和稳定性
- `tools`：开发工具、AI IDE、MCP、CLI、浏览器自动化
- `products`：AI 产品设计、原型验证、真实用户反馈
- `projects`：学生项目路线和案例
- `resources`：文章、课程、文档、论文和开源项目索引

现在先写 [[Agent]]。你可以先从 [[Agent]] 开始。

每个方向会尽量回答同一组问题：

- 信息来源：去哪里跟进这个方向的靠谱信息
- 开源项目：哪些项目可以看，分别能学什么
- 概念地图：至少要理解哪些概念，以及它们之间的关系

每个方向下的内容会保持笔记化，不写成一本必须从第一页读到最后一页的书。你可以从一个项目出发，跳到需要的技术方向，再顺着链接继续读。

## 阅读体验

这个仓库本质上会是一个 Markdown 笔记库。

后续内容会使用和 Obsidian 兼容的双向链接语法，例如：

```md
[[RAG]]
[[Agent]]
[[Context Engineering]]
```

仓库内部的知识关系统一使用双括号双向链接。外部网站、论文、GitHub 项目和官方文档仍然使用普通 Markdown 链接。

如果你直接在 GitHub 上阅读，也可以正常查看 Markdown 文件。

如果你想要笔记索引和双向链接体验，可以使用 **Lumina Note**。它是面向 Markdown 笔记的阅读和索引工具，支持和 Obsidian 相同的双向链接语法，用来浏览这种非线性知识库会方便一些。

## 推荐学习方式

不要把这个仓库当成收藏夹。

建议这样用：

1. 先读路线，知道自己处在哪一层
2. 选一个小项目，尽快做出可用版本
3. 遇到不会的技术，再去查对应资源
4. 做完后复盘：哪里不稳定，哪里不可扩展，哪里只是 demo
5. 继续迭代，不要换一个新概念重新收藏

## 贡献方式

这个仓库欢迎贡献，但希望保持克制。

欢迎贡献的内容：

- 靠谱学习资源链接
- 清晰的项目路线
- 对某个概念的简洁解释
- 真实踩坑记录
- 对低质量资源或误导性路径的辨析

暂时不收的内容：

- 大而全的资料堆砌
- 没有验证过的学习路线
- 单纯搬运别人的文章
- 培训班式营销内容
- 只服务于传统面试八股的内容
